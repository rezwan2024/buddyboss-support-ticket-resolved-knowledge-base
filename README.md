# BuddyBoss support ticket resolved knowledge base

Short cases written from resolved BuddyBoss support tickets. Each case is generalized: all customer data (names, emails, sites, credentials, keys) is removed before it is pushed, and every case passes `scripts/check_masking.py`.

## Case format

`cases/<ticket number without last two digits>/<ticket>.md`, with `-2`, `-3` for further issues in the same ticket.

```
---
title: long searchable title
type: app | web | addon | integration | account
fix: confirmed | unconfirmed
error: exact error text or code, or empty
keywords: comma separated
---
## Debugging steps
1. step
2. Ruled out: what was checked and was not the cause

## Solution
The fix in one to three lines. Root cause: one line.

## Customer note
What the customer said in their last reply, one short line.
```

`fix: confirmed` means the Jira PROD fix was released, or the customer said it is solved, it worked, or thanked for the fix. Everything else is `fix: unconfirmed` and is a lead only. `index/unconfirmed.md` lists them for review.

## Index

Everything in `index/` except `synonyms.json` is generated by `scripts/build_index.py` from the case headers and is never edited by hand. `synonyms.json` maps customer words to KB words and is hand maintained. `scripts/normalize.py` holds the shared word rules used by both the index and the search script.

`tests/search-cases.tsv` holds sample queries and the case each must find. `build_index.py` runs them after every build.
