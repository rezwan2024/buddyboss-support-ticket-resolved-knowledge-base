## Debugging steps
1. Enabled reCAPTCHA v3 with Reset Password turned on under Enabled for.
2. As administrator, clicked Send Reset Link on a user profile: "Google reCAPTCHA token is missing." and no email sent.
3. Used the Users list row action and the bulk action Send password reset: "Password reset link sent to 0 users." and no email sent.
4. Checked the code: the lost password reCAPTCHA check runs on the lostpassword_post hook for every retrieve_password() call and only skips REST requests, so admin resets reach it with no token.
5. Ruled out: site specific setup. Reproduced on Platform 3.5.1 and 3.6.0.

## Solution
Update BuddyBoss Platform to 3.7.0 or later, where admin password resets no longer go through the reCAPTCHA check.
Workaround before updating: use the bb_recaptcha_rest_api_bypass filter to return true for users with the edit_users capability when the request is the send-password-reset AJAX action or the resetpassword action on users.php.
Root cause: the reCAPTCHA check on lostpassword_post did not tell front-end lost password form submits apart from admin started resets, which have no token.
