## Debugging steps
1. Confirmed the tester device UDIDs were registered in the Apple Developer account and in BuddyBoss App.
2. Followed the KB article on the "Integrity could not be verified" error for iOS test apps: Apple Developer connection, UDID registration, fresh build after adding UDIDs.
3. Checked that all certificates in the Apple Developer account are valid and not expired.
4. Ruled out: Android build, it installed and worked normally.
5. Same Ad Hoc build started installing on one device days later without changes, pointing to Apple provisioning sync rather than the build itself.

## Solution
Generate a new Test App build only after all UDIDs are added and saved. If testers still cannot install, stop using the Ad Hoc Test App for client testing and distribute a Release App build through TestFlight instead (no UDID registration needed), see case 156475-2. This is a workaround.
Root cause: Ad Hoc Test App installs depend on the device being in the provisioning profile of that build, and Apple provisioning can lag after new devices are added.
