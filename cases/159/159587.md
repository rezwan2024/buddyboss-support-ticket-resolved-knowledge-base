## Debugging steps
1. Reproduced: on the activation page the header shows the new username, but message and notification counts and message previews from other members; message links lead to 404. On the next page load the account's own data shows correctly.
2. Ruled out: browser cache and cookies, custom messaging plugin (deactivated), Platform update from 3.5.0 to 3.5.1.
3. Ruled out: server or page caching and the site's custom code snippets.
4. Tested the activation flow live with a single test account bypass and found German Market double opt-in logs the customer in partway through loading the activation page.

## Solution
Stop German Market from logging the customer in after activation. Add as a PHP snippet with a code snippet plugin:
```php
add_filter( 'german_market_double_opt_in_login_after_activation', '__return_false' );
```
The account is still activated and the password setup email is still sent; the customer sets the password and logs in normally.
Root cause: German Market logs the user in during the same page load after BuddyBoss has already set up the page for a logged-out visitor, so header counts and message dropdown are not limited to the new account.

## Customer note
Said the fix works exactly as intended, no member data shows after activation, and thanked the team.
