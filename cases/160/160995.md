## Debugging steps
1. Confirmed the only file that needs wp-content/mu-plugins is the API Caching plugin from the optional API Performance component in the BuddyBoss App plugin.
2. Ruled out: BuddyBoss Platform, the theme and the app itself do not depend on the mu-plugins folder.
3. Checked with the development team for a setting, filter, other folder or regular plugin option to load API Caching. None exists, because the cache must start before WordPress loads other plugins and the theme.
4. Ruled out: a site-side cause. The read-only mu-plugins folder is specific to the host's Agency plan.

## Solution
Switch off the API Performance component in the BuddyBoss App settings. The site and app keep working normally without API Caching, which is only an optional speed layer for the app.
To use caching, move to a hosting plan that allows writing to wp-content/mu-plugins, then enable API Performance so the caching plugin installs there. There is no other way to run it.
Root cause: API Caching can only run as a must-use plugin, and the host blocks writes to the mu-plugins folder.

## Customer note
Thanked the team and said they will move to a hosting plan that allows mu-plugins later.
