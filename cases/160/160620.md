## Debugging steps
1. Checked the SMTP email log: one activity update notification was sent to the same group of members many times, every 5 minutes, until it stopped by itself.
2. Ruled out: the mail server did not reject any emails.
3. Ruled out: the PHP max execution time was not the limit.
4. Found that each background send run was cut off after a few emails, and the next cron run started again from the first member, with no WordPress error recorded.
5. Asked for the server PHP error log for the loop time, the wp-cron.php cron command and server file access, and had WordPress error logging enabled to catch the next cut-off.

## Solution
BuddyBoss sends notification emails in the background one member at a time. When the server kills the PHP process mid-batch, the batch restarts from the start and members get duplicates. Check the server PHP error log at the loop time for what kills the process, enable error logging, and run wp-cron.php from a real server cron instead of WordPress page-load cron. The loop stopped on its own and later notifications went out once per member.
Root cause: something on the server stopped the PHP background email process mid-batch, so each new cron run resent from the first recipient.
