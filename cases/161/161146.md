## Debugging steps
1. Read the stack trace: disable_yoast_seo() in Plugin_Compatibility.php runs on the wp hook and calls WPSEO_Frontend::get_instance().
2. Ruled out: caching, the error stays after clearing all caches and updating Sharing to the latest version.
3. Deactivating BuddyBoss Sharing stops the error, so the add-on is the source.
4. Reproduced with Yoast SEO active: current Yoast versions no longer have the WPSEO_Frontend class, so every front-end request fails.

## Solution
Update BuddyBoss Sharing to v2.1.2 or later, which has the official fix.
Workaround before the update: back up and edit wp-content/plugins/buddyboss-sharing/includes/Modules/Plugin_Compatibility.php around line 134, replace the line below (the code after it already checks $frontend). A Sharing update overwrites this edit.
```php
// Find:
$frontend = \WPSEO_Frontend::get_instance();
// Replace with:
$frontend = is_callable( array( '\WPSEO_Frontend', 'get_instance' ) ) ? \WPSEO_Frontend::get_instance() : null;
```
Root cause: Sharing called the WPSEO_Frontend class without checking that it exists, and current Yoast SEO versions removed it.

## Customer note
No reply after the workaround and the release notice; fix released in Sharing v2.1.2.
