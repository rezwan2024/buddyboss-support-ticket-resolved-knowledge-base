## Debugging steps
1. The items were saved under Menus > Header Bar, More Menu placement was set to Top Header Bar, and the records were in the database. The admin preview showed them.
2. Ruled out: caching alone. Deleting and rebuilding the header bar menu, clearing server, object, app API and plugin caches, and doing new builds changed nothing.
3. Ruled out: the App Core version (3.1.7) differing from the App plugin version (3.2.1).
4. Called the app's menu API directly. The response had the Tab Bar and More Menu items, but the header bar section was empty. The post button came from a separate part of the response.
5. Found that the Tab Bar menu links to the Header Bar menu by an ID reference. The admin finds the header bar menu by type, but the app API uses the ID reference, and that reference pointed to an old ID.

## Solution
Update the stored ID references so they point to the current Header Bar menu ID. Do not delete and rebuild the menu again. Then clear the BuddyBoss App API cache, the caching plugin cache and the stored transients. No new app build is needed, because existing builds pick up the change.
Root cause: Deleting and recreating the header bar menu in the database gave it a new ID, but the Tab Bar menu still pointed to the old ID, so the app API returned an empty header bar. Each repeat of the delete made the mismatch happen again.
