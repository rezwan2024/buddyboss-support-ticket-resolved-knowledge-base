## Debugging steps
1. Reproduced on a clean install: added a WordPress Page to the More menu, enabled "Always open in external browser", saved. The setting stayed enabled, so the cause is site specific.
2. Checked the Save Menu POST request in the browser dev tools: it contains `appmenu-item[ID][data][open_external] = yes` and returns the "menu has been updated" notice.
3. Ruled out: browser side. The value is sent correctly; it is lost on the server or replaced by a cached copy on reload.
4. Ruled out: font CORS errors in the console. They only affect font loading.
5. Asked about caching and security plugins. The site used a page/object cache plugin and Wordfence.

## Solution
Not confirmed; the customer stopped replying. Next steps given: clear all caches including the object cache, then reopen the menu item. If still unchecked, run a plugin conflict test with only BuddyBoss Platform, BuddyBoss App and BuddyBoss Theme active, with the cache and security plugins deactivated, on staging.
Root cause: not confirmed; most likely a stale object cache or a cache or security plugin dropping the saved menu value on the server.
