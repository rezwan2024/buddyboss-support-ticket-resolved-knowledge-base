## Debugging steps
1. Confirmed the generated language file in uploads/ldapp/language/ is valid JSON ({"en":[]}) and returns HTTP 200 with no redirect. A 2xx response with data is accepted by the build service, so a tiny file is fine.
2. Ruled out: host CDN cache, host bot protection and redirect rules. The build service request never showed up in the host access logs.
3. Ruled out: Cloudflare proxy and WAF. The build still failed with DNS switched to DNS only.
4. Tested with the build service user agent: curl -I -A "BuddyBossBot/1.0 BuddyBoss Bot" <language file URL>. It returned 200, so a user agent block was not the cause.
5. Updating the LearnDash App plugin to the latest release did not fix it.

## Solution
Workaround patch in the LearnDash App plugin: in Build/Build.php, inside get_review_information, right after the language_json entry is set up, add the translations file to the files sent with the build request. The build service then no longer downloads it from the site, and the build completed.
A plugin update overwrites this patch until LearnDash releases the permanent fix, so the customer has to pass it to LearnDash support.
Root cause: on some sites the build service cannot download the language file from the site itself, even when the file is publicly reachable.
