## Debugging steps
1. Ruled out: plugin conflict. With only BuddyBoss Platform and Platform Pro active, new Header Bar items (App Core > Profile, Logged-in Member > Profile) still vanished after saving.
2. Ruled out: plugin versions. The problem stayed after updating all plugins.
3. Opened the browser console while clicking Save Menu and saw "AbortError: Transition was skipped", which stopped the save before it finished.
4. Ruled out: wp_options. The header bar data is not stored there. It is in the BuddyBoss App custom tables.
5. Tab Bar and More Menu saved fine, so only the Header Bar menu data was damaged.

## Solution
Back up the database. In phpMyAdmin, open the wp_bbapp_menus table, note the id of the row where menu_type is headerbar and delete that row. Then delete every row in wp_bbapp_menu_items whose menu_id matches that id. Rebuild the menu from scratch under BuddyBoss App > Menus > Header Bar. Try it on staging first.
Root cause: Damaged Header Bar menu records in the BuddyBoss App menu tables broke the save. Note: the delete creates a new Header Bar menu ID. If the items later do not show in the app, see case 148856-2.
