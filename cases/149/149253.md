## Debugging steps
1. Checked the build log: the build stopped at the splash screen step because the splash logo could not be read.
2. Ruled out: the image. The customer re-exported the logo as a clean 1024x1024 PNG several times and also tried the BuddyBoss demo branding images, and the build still failed.
3. Ruled out: dark mode and the multisite setup. Turning dark mode off did not help, and multisite was not the cause.
4. Escalated to the app dev team: the site uploads the whole build package to the build server in one request, and that upload hit a fixed timeout and was cut off. The files that did not arrive were saved broken, so the build failed on the first one it opened, which was the splash logo. Classic builds worked because the Classic package is small enough to finish before the timeout.
5. After the plugin update the build still failed because Cloudflare challenged the build server when it fetched app assets.

## Solution
Update the BuddyBoss App plugin to the release that fixed the build package upload timeout. If the site uses Cloudflare, add a WAF custom rule with the action Skip (Super Bot Fight Mode, Browser Integrity Check, rate limiting and managed rules) for URI paths starting with /wp-json/ or /wp-content/uploads/, or user agent containing BuddyBossBot. If it still fails, turn Bot Fight Mode off while you send the build request, then turn it back on. Then send a new Android Next Gen build.
Root cause: the build package upload was cut off by a fixed timeout and Cloudflare bot protection blocked the build server, so the build saw broken asset files. The splash logo error was misleading.
