## Debugging steps
1. Ruled out: license. It was active and in good standing; a license status check warning on the site was not the cause.
2. Traced the request: the site's admin-ajax call bbms_stripe_connect_launch returned 200 with the auto-submit form, then the POST to stripe.buddyboss.com/connect returned 404 from the BuddyBoss service itself.
3. Ruled out: plugin conflict and site webhooks. The 404 came before the site was involved and the webhook endpoints responded normally.
4. Reproduced the full Connect with Stripe flow on a clean test site with Membership 1.14.2; it returned the same 404 once past the login step.

## Solution
Update BuddyBoss Membership to 1.14.3, then click Connect with Stripe again under Memberships > Settings > Payments and run a test checkout in Stripe test mode.
Temporary workaround before the release: roll back Membership to 1.14.1 (Downloads > Other versions, upload with Replace current with uploaded), but 1.14.1 has a checkout fatal error, see case 162216-2.
Root cause: a bug in Membership 1.14.2's Stripe Connect flow made the BuddyBoss Stripe Connect service return 404, fixed in 1.14.3.
