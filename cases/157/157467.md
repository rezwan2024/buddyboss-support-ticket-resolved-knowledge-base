## Debugging steps
1. Host reported large bb_documents and bb_medias folders under wp-content/uploads and asked which files are safe to delete.
2. Admin and SFTP access was asked for to check the files, but the customer could not share access.
3. Explained that files in these folders are linked to database records, so deleting live files breaks media in posts, profiles and messages.

## Solution
Compare a per-file listing of wp-content/uploads/bb_documents, bb_medias and bb_videos (path, size, modified date, from the host) with a read-only database export of files still in use, then review only files on disk that are not in the export. Take a full site and database backup first.
```sql
SELECT m.id, m.user_id, m.attachment_id, pm.meta_value AS file_path, m.date_created
FROM wp_bp_media m
LEFT JOIN wp_postmeta pm ON pm.post_id = m.attachment_id AND pm.meta_key = '_wp_attached_file';
```
Repeat with wp_bp_document and wp_bp_video, adjusting the table prefix if needed.
Root cause: user-uploaded media and documents grow over time and orphaned files from deleted content are not removed from disk.
