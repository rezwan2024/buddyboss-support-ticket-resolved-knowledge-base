## Debugging steps
1. Username and password are accepted and the Wordfence 2FA screen shows, but the valid 2FA code fails or the Log In button does nothing.
2. Ruled out: server clock drift and a bad 2FA secret, since a new authenticator secret failed the same way.
3. Ruled out: Wordfence's own reCAPTCHA (off) and ModSecurity (it only logged warnings for g-recaptcha-response).
4. BuddyBoss validates reCAPTCHA on the WordPress authenticate filter (bb_recaptcha_validate_login, priority 99999), so the Wordfence 2FA second step also gets checked.
5. Setting only bb_login to 0 in the bb_recaptcha option made Wordfence 2FA login work right away.

## Solution
Workaround: turn off BuddyBoss reCAPTCHA for the login form only (bb_login set to 0 in the bb_recaptcha option) and keep it on for registration and lost password. Use Wordfence 2FA on login.
Option not tested: use Wordfence's own reCAPTCHA v3 (Wordfence > Login Security > Settings > reCAPTCHA, with its own Google keys) on login, and keep BuddyBoss reCAPTCHA on registration. Keep an admin session open while you test it.
Root cause: the BuddyBoss reCAPTCHA check on the authenticate filter fails the Wordfence 2FA second-step login request, which has no valid reCAPTCHA token.
