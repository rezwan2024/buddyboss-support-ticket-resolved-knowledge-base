## Debugging steps
1. Confirmed the Zoom component is off but Platform Pro still loads bp-zoom.min.css and bp-zoom.min.js on the homepage, plus MemberPress Courses and Tutor LMS admin styles even though MemberPress is not installed.
2. Ruled out: the react-dom file in the report comes from the Gutenberg plugin, not BuddyBoss.
3. A first snippet dequeuing only the Zoom, MemberPress and Tutor LMS files gave no visible gain; buddypress.min.css was the main offender.
4. Measured the homepage use of buddypress.min.css (under 1% of rules matched); the only user was the hidden Report and Block Member modal in the footer, which that file keeps hidden.
5. Ruled out: a PHP warning seen while testing came from another snippet on the site using an undefined variable, not from the BuddyBoss snippet.

## Solution
Add as a PHP snippet with a code snippet plugin. It dequeues the BuddyBoss files on the front page only and keeps the report modal hidden:
```php
add_action( 'wp_enqueue_scripts', function () {
	if ( ! is_front_page() ) { return; }
	foreach ( array( 'bp-nouveau', 'bp-nouveau-icons-map', 'bp-mentions-css', 'bp-zoom', 'bb-meprlms-frontend', 'bb-tutorlms-admin' ) as $h ) { wp_dequeue_style( $h ); }
	foreach ( array( 'bp-zoom-js', 'bb-meprlms-frontend', 'bb-tutorlms-admin' ) as $h ) { wp_dequeue_script( $h ); }
}, 100 );
add_action( 'wp_head', function () {
	if ( is_front_page() ) {
		echo '<style>.bp-hide,.bbm-model-wrap,.modal-mask,#bp-report-content,.bp-report-form-err{display:none !important;}</style>';
	}
} );
```
Workaround for sites whose homepage has no BuddyBoss content. Keep the wp_head part, or the Report modal shows below the footer.
Root cause: BuddyBoss Platform and Platform Pro enqueue their CSS and JS on every page, including disabled components and integrations.

## Customer note
Said the BuddyBoss scripts were gone, the homepage loads almost 1000 ms faster and pages look fine; turned the snippet back on.
