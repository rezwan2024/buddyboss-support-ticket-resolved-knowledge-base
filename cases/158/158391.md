## Debugging steps
1. Checked whether the Apple ID had signed into the app before. Apple sends the name only on the first authorisation for an app, so a name entered on later sign ins never reaches the site.
2. Ruled out: a custom signup step. The customer removed the app from the Apple account first and used the app with no custom changes.
3. Checked BuddyBoss > Settings > Profiles > Profile Name. Display Name Format was First Name & Last Name, which makes those profile fields required, so the app shows an extra name form after Sign in with Apple.
4. Checked the social login settings. Pull Additional Data from Social Account > Name was enabled, so the Apple account name fills First Name and Last Name automatically.

## Solution
Set Display Name Format to Nickname, make the First Name and Last Name profile fields optional (or turn them off under Display Name Fields), run the Repair Community tool shown below the setting and clear the site cache. Then request a new iOS build, upload it to App Store Connect and resubmit, telling Apple the only field left after Sign in with Apple is the username.
A first and last name form cannot be forced after Sign in with Apple. Keep Pull Additional Data > Name enabled so names still sync. Users who hide their name in Apple can add it later from their profile.
Root cause: required First Name and Last Name fields made the app ask again for data Apple already provides, which Apple review rejects.
