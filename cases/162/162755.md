## Debugging steps
1. Homepage went to 404 several times a day and came back only after a cache clear or post update.
2. Reproduced on a clean site: WooCommerce 11.2.1, Platform 3.6.2, persistent object cache, static front page. Load a member profile, send /?wc-ajax=get_refreshed_fragments with that profile URL as the referer, then load the homepage.
3. Checked the Platform code: during AJAX, bp_core_filter_wp_query() reads the page path from the referer. With a member profile referer it empties the main query for the front page, and the object cache stores that empty result under the front page query key.
4. Ruled out: hiding the theme header cart icon was not enough, since the WooCommerce cart script still loaded on member profiles for logged-out visitors.

## Solution
To bring the homepage back right away, open the static front page and click Update without changing anything. This refreshes the cached query.
Temporary fix: a snippet added with a code snippet plugin that makes BuddyBoss use the real request address, not the referer, for WooCommerce wc-ajax cart requests only. After that, a cart refresh from a member profile did not affect the homepage. Profiles, activity and shop still loaded normally. The fix was then passed to development for the plugin.
Root cause: during WooCommerce cart fragments AJAX, bp_core_filter_wp_query() uses the referer's member profile path and returns an empty front page query, which the persistent object cache serves to every homepage visitor.
