## Debugging steps
1. Checked debug.log after the 3.2.8 to 3.2.9 update: fatal in create_default_apppage() at NativeAppPage.php line 1503, reached from the legacy database update.
2. Found the database update runs while the plugin is still loading, before WordPress defines wp_get_current_user().
3. Confirmed it only triggers when no app page titled "Home" exists (any status except trash), and the new database version is never saved, so every request crashes again.
4. Rolled the plugin back to 3.2.8: site and app web fallback worked again, database version unchanged.
5. Matched the trace to another identical report and escalated to the App development team.

## Solution
Update the BuddyBoss App plugin to 3.2.10, which contains the permanent fix. Until then, stay on 3.2.8 or install the patched build from support (Plugins > Add New > Upload Plugin > Replace current with uploaded).
Untested workaround suggested on staging: create an app page titled "Home" (draft is enough) before updating to 3.2.9, so the update skips the crashing branch.
Root cause: 3.2.9 ran its database update during plugin load and called wp_get_current_user() before WordPress loaded it when no Home app page existed.
