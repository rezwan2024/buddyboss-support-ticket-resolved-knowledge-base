## Debugging steps
1. Registered a new account as a normal visitor with a Gmail address: the form completed but the activation email never arrived.
2. Asked the customer to repeat the test with a Gmail address, then again with the new bot protection changes temporarily disabled, to see if they block the email.
3. Asked to check whether the activation email is sent, fails or is never triggered, using an SMTP plugin email log.

## Solution
Suggested steps, not confirmed: temporarily remove custom bot protection code and test registration again. Install FluentSMTP, connect it to Gmail, Brevo or the host's SMTP, send a test email, then try a new registration and check the email log.
If the log shows no activation email was triggered, the bot protection is stopping registration before the email step. If it shows a failed send, the server mail function is the problem.
Root cause: not identified in the ticket. Most likely the custom bot protection or the server's default mail function.

## Customer note
Said they fixed all the issues themselves and no further investigation was needed. The exact fix was not shared.
