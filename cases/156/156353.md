## Debugging steps
1. Customer reported that newer emojis (for example 1fae9) inserted from the BuddyBoss emoji picker load from an emoji URL fixed to version 14.0.0, which returns a 301 and a blank image.
2. Asked for a screen recording or screenshots, the browser Network tab with the failed request, and WordPress and Platform versions, and to test with only Platform active and a default theme.
3. Tested the same emoji in a private message and an activity post on a test site: it rendered correctly, and no similar reports from other customers.
4. Asked the customer to remove their workaround snippet first, since it hands emojis to WordPress core and hides the original behavior.
5. Customer replied with BuddyBoss Platform 3.0.3, WordPress 7.1, a non-English site language, and said it happens in messages, posts and comments alike.

## Solution
Workaround from the customer: stop the BuddyBoss emoji scripts so WordPress core renders the emojis, added with a code snippet plugin:
```php
add_action( 'bp_enqueue_scripts', function() { wp_dequeue_script( 'bb-emoji-loader' ); wp_dequeue_script( 'bb-twemoji' ); }, 100 );
```
Not reproduced on a test site yet, so no product fix was confirmed.
Root cause: reported as the emoji base and SVG URLs in bp-core-cssjs.php being fixed to emoji version 14.0.0 instead of the current WordPress emoji version.
