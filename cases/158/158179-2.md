## Debugging steps
1. Host checked server access logs: the 403 came from the origin on GET signup/form from many different IPs.
2. Ruled out: server WAF or ModSecurity, no matching denial in its logs, and the login rate limit only watches wp-login.php.
3. Ruled out: many IPs as a sign of an attack. The app calls signup/form before login to load the registration form, so each device is a separate IP.
4. Check registration settings: BuddyBoss > Settings > General, Allow non-members to create new accounts, and BuddyBoss App > Settings > General, Allow registering a new account from within the app.
5. Check BuddyBoss > Settings > Advanced > Privacy for Private REST APIs, and the Private App option in BuddyBoss App settings. Both block API access for logged-out users.
6. Check security or performance plugins (Wordfence, Solid Security, All In One WP Security, Perfmatters, Disable REST API) for an option that blocks the REST API for logged-out visitors.

## Solution
Run curl -i against the signup/form endpoint while logged out. A JSON body with a "code" value means WordPress or a plugin returned the 403 and the code names the source; an HTML error page points to the web server configuration.
Turn on both registration settings and turn off the setting or plugin option that blocks REST API access for logged-out users.
Root cause: not confirmed; likely a site setting or plugin blocking the REST API for logged-out requests, since the server firewall was ruled out.
