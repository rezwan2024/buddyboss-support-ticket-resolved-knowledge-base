## Debugging steps
1. Pointed to Memberships > Import, which imports users, subscriptions and transactions from CSV.
2. Confirmed WooCommerce Subscriptions handles renewals itself and only sends charges to Stripe, so no subscriptions exist in Stripe.
3. Confirmed with the development team that BuddyBoss Membership does not charge saved cards itself. It needs a Stripe subscription and records renewals when Stripe confirms payment, so importing alone moves records and access but not billing.
4. Ruled out: no built-in way for WooCommerce Subscriptions status to grant or revoke BuddyBoss Courses access, since access follows BuddyBoss Membership rules.

## Solution
Connect BuddyBoss Membership to the same Stripe account. Use the Stripe API (a small script) to create a Stripe subscription on each customer's saved card, with the first charge on their next WooCommerce renewal date. Import those subscriptions and last payments with Memberships > Import, then cancel the matching WooCommerce subscriptions at cutover so nobody is charged twice. Test with one or two customers first. Cards saved in Stripe's older format may need updating.
Simpler option: import students for access only, expiring on their next renewal date, and have them re-subscribe through BuddyBoss checkout. Keeping WooCommerce for billing would need a custom plugin.
Root cause: WooCommerce Subscriptions keeps the billing schedule inside WooCommerce, not in Stripe, and BuddyBoss Membership billing relies on Stripe subscriptions.
