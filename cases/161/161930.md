## Debugging steps
1. Checked the PHP error log: fatal error in NativeAppPage.php line 1503 while plugins were still being included.
2. Traced the call path: Brand Backward load() -> handle_legacy_updates() -> LegacyUpdater::run_legacy_updates() -> on_database_update() -> NativeAppPage::create_default_apppage() -> wp_get_current_user().
3. Confirmed it triggers when the stored App DB version is below the target and no app page titled "Home" exists, so the default page creation calls a pluggable function before pluggable.php is loaded.
4. Ruled out: OPcache, clearing it did not help; PHP version, no rollback needed.

## Solution
Update the BuddyBoss App plugin to 3.2.10, which runs the legacy migration only after WordPress functions are loaded.
Temporary workaround before the update: add a guard at the start of LegacyUpdater::run_legacy_updates() in the plugin so the migration is deferred to plugins_loaded (lost on plugin update):
```php
if ( ! did_action( 'plugins_loaded' ) ) {
    add_action( 'plugins_loaded', array( $this, 'run_legacy_updates' ), 0 );
    return;
}
```
Root cause: App 3.2.9 ran the legacy DB migration during plugin inclusion, before WordPress loaded pluggable.php, so wp_get_current_user() was undefined.
