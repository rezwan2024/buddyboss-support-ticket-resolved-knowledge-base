## Debugging steps
1. Checked the new BuddyBoss 3.0 Profile Fields admin screen: fields are edited in a popup and the field ID is not shown anywhere, so no setting is missing.
2. Ruled out: a hidden option to show the ID in the new admin screen.
3. Confirmed the ID is still readable on the front end Edit Profile form, where each input has a name and id like field_12.

## Solution
Open your own profile on the front end, go to Edit Profile, right click the field and choose Inspect: the number after field_ in the input name or id is the field ID. Fields limited to certain profile types only show for a member of that type.
With WP-CLI, `wp bp xprofile field list` lists every profile field with its ID. For syncing IDs to an external system, a GET request to the BuddyBoss REST API profile fields endpoint returns every field with its id and name (needs a logged-in user when the private network option is on).
Root cause: the BuddyBoss 3.0 admin rebuild moved profile field editing from a separate page (ID in the URL) to a popup that does not show the ID; feedback passed to the product team.
