## Debugging steps
1. Checked how the app requests language content: it sends an appLang HTTP header with each API call and falls back to the site or WPML default locale.
2. Confirmed the app API looks up translated posts, pages, courses and events only through WPML functions.
3. Ruled out: Polylang and Loco Translate as a source of per-language content in the app. Polylang still works for the website only.
4. Confirmed app interface strings are managed separately in BuddyBoss App > Translations, not in the theme or Platform plugin.

## Solution
Use WPML for any WordPress content that must vary by language inside the app. Enable the languages (French and German ship natively) as Active Languages in BuddyBoss App > Translations and adjust wording with CSV export/import. One build is needed to register the languages; later text edits are live without a rebuild.
Root cause: The app API is wired to WPML only, and Loco Translate strings do not carry over to the app's own translation system.
