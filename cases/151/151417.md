## Debugging steps
1. Checked the bbapp folder under the uploads folder (on multisite, under the subsite uploads folder) for stored app credential files.
2. Found the app's push notification and app signing credential files stored there.
3. Confirmed the credential subfolders have no index.html, no .htaccess and no deny rule, and the plugin has no code that writes one. Protection relied only on hashed filenames.
4. Confirmed the files are only hidden when the server has directory indexing turned off; with indexing on, the folders list their contents.
5. Escalated to the product team, who added protection in a later release.

## Solution
Update the BuddyBoss App plugin to v3.2.7 or later, which adds access protection for the credential folders.
Workaround until updated: add a server deny rule (nginx location block or Apache .htaccess deny) for the bbapp credential folders in uploads and keep directory indexing off.
If the files may have been reached from outside, check the access logs and replace the push and signing credentials.
Root cause: the plugin saved credential files into the publicly served uploads folder without adding any access control.
