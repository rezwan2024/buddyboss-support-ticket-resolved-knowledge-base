## Debugging steps
1. Tried to reproduce on a clean local install. It did not reproduce.
2. Created a new test account on the affected site and changed its password from the profile Settings page. The issue reproduced.
3. Ruled out: the WordPress lost password flow, which saved the new password correctly.
4. Found several site-specific custom plugins hooking into signup, registration and password handling. Turned them off for a test and the password change then worked.

## Solution
Disable or fix the custom plugins that hook into signup, registration or password reset, then retest the password change from the profile Settings page. Their code needs a developer review.
Root cause: a site-specific custom plugin conflict blocked the password from being saved.

## Customer note
Thanked the team and said their developer would fix the custom plugins. They did not confirm the fix.
