## Debugging steps
1. Customer logged out of the app to retry and could not log back in; the app showed a WordPress REST API error while the website kept working.
2. Ruled out: site content, since groups, forums and blogs all went blank in the app at once, which points to the API layer.
3. Opened the REST API index as administrator and checked that the buddyboss/v1 namespace is listed (404, login screen or blank page means the API is not reachable).
4. Checked BuddyBoss > Dashboard for the option to restrict REST API access to logged-in members, and checked security plugins, firewall and CDN for blocked /wp-json/ requests.
5. Checked that WordPress Address and Site Address in Settings > General match the domain the app was built for (https and www form), and that BuddyBoss Platform and BuddyBoss App are active and updated.

## Solution
Re-save Settings > Permalinks with the Post name structure to regenerate the REST API rewrite rules, allow /wp-json/* in any security plugin, firewall or CDN, then purge all server, plugin and CDN caches.
Turn off the REST API restriction to logged-in members if enabled, make sure the site URLs match the app domain, then fully close and reopen the app before testing.
Root cause: REST API requests from the app did not reach the right endpoint after the site was renamed and updated (stale rewrite rules or blocked /wp-json/ requests).
