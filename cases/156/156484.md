## Debugging steps
1. Checked the Apple rejection notice: Guideline 4 because the app asks for name or email after the user already signed in with Apple.
2. Checked the site registration setup: BuddyBoss registration enabled, with required profile fields shown after Apple sign in.
3. Ruled out: enabling the last name field did not help, the next build was rejected again.
4. Checked the live iOS app and reproduced the extra details screen after Sign in with Apple.

## Solution
Set the first name and last name profile fields to not required, so they no longer show in the Sign in with Apple flow. For the username field that still shows, reply to the App Store reviewer that the username is part of the signup process and is not returned by Apple, and the reviewer approved the app.
Root cause: required profile fields on the site registration were shown after Sign in with Apple, which Apple treats as asking again for data it already provides.

## Customer note
Said it is fixed now and shared the steps that got the app approved.
