## Debugging steps
1. Opened the member's Account Settings > Notification Settings on the frontend and reproduced the critical error.
2. Found that some notification types had no stored On/Off value.
3. Confirmed that on PHP 8 a missing value makes the Platform notification settings page stop loading.

## Solution
In the admin dashboard go to BuddyBoss > Settings > Notifications, enable the notification types and save. This stores a proper On/Off value for all types without editing the database. Workaround until a permanent fix ships; turn off again any types you do not want, as some that were off become enabled.
Root cause: Notification settings missing their On/Off value break the Platform notification settings page on PHP 8.

## Customer note
No direct reply on the fix; the customer went on to change the digest setting, so the page loaded again.
