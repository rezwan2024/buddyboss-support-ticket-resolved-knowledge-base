## Debugging steps
1. Confirmed the issue started right after updating BuddyBoss Platform 3.6.1 to 3.6.2 (with Platform Pro, Theme and add-ons) from the WordPress dashboard, and that self-deletion worked before.
2. Confirmed the update package came from the normal dashboard updater, not a manual download.
3. Asked the customer to test on a staging site with only BuddyBoss plugins active, with Paid Memberships Pro, its add-ons and other third-party plugins turned off, to tell a BuddyBoss change from a plugin conflict.
4. Advised against testing deletion or plugin deactivation on the live site, because it can affect memberships and user data.

## Solution
No code change. The customer let the site settle for a while after the updates and tested front-end account deletion again. Deletion then worked normally: no replacement user, no email-changed notice.
If it keeps happening, test on staging with only BuddyBoss active to check for a Paid Memberships Pro or other plugin conflict.
Root cause: temporary behavior right after the plugin updates, most likely while caches or update routines were still finishing. Not reproduced later.

## Customer note
Said the deletion issue was resolved after retesting later and thanked the team.
