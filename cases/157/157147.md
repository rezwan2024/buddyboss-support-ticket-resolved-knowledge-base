## Debugging steps
1. Asked which colors revert and for a screen recording of the save.
2. Updated the BuddyBoss App plugin to the latest version and cleared plugin, server, object, CDN and browser caches: issue persisted.
3. Ruled out: plugin or database fault. Not reproducible on the staging copy, which is not behind the same host cache.
4. On live, changed the Primary color and saved: screen showed the old color. After Purge All Caches in the host caching panel and a reload, the new color appeared. Repeats on every change.
5. Ruled out: object cache only. Purging only the WP object cache was not enough.

## Solution
Workaround: after saving branding colors, purge all caches in the host caching panel (Pressidium, Adaptive Caching, Purge All Caches), then reload the app branding settings page.
Permanent fix is on the host side: ask the host to stop caching the wp-admin app settings screen for logged-in administrators.
Root cause: the host page cache served a cached copy of the admin branding screen even for logged-in admins, so saved colors looked like they reverted.
