## Debugging steps
1. Checked the BuddyBoss Membership plan settings: a plan has no direct link to a WordPress role or a profile type.
2. Checked BuddyBoss > Settings access controls (groups, activity, messages, media, connections): they include a Membership condition, so the plan itself can be the access rule.
3. Checked BuddyBoss > Settings > Member Profile > Profile Types: each profile type has a WordPress Role setting that sets the role when the profile type is assigned, existing users included.
4. Checked Memberships > Import: accepts CSV files for users, memberships and subscriptions.

## Solution
Use the membership plan as the access condition (Access Controls Membership condition, plan-linked groups, profile page protection, restricted pages, posts and courses). If profile types stay, map each profile type to a role. Assigning a profile type on plan join is not built in and needs a custom snippet.
Recreate the PMPro levels as plans, then import subscriptions via Memberships > Import (full database backup, staging first). Keep PMPro active until access is verified, then deactivate it. Remove any old custom rules protecting /members/ before using profile page protection. For paid plans later, connect Stripe under Memberships > Settings > Payment Methods and test in test mode first.
Root cause: BuddyBoss Membership controls access by plan, not by role or profile type, so no direct plan-to-role mapping exists.
