## Debugging steps
1. Customer created the Zoom app and entered Account ID, Client ID and Client Secret in BuddyBoss Zoom settings; the Account Email dropdown stayed empty and Update could not be clicked.
2. Found that Zoom redesigned its Developer platform and renamed scopes (granular permissions), so the old guide and video no longer matched one to one.
3. Ruled out: Zoom developer account email does not need to match the WordPress admin email; the dropdown lists users on the Zoom account tied to the credentials.
4. Ruled out: Zoom user role; the account was Owner, so admin-level scopes were allowed.
5. Checked that the app has user read access and is reactivated after scope changes, then credentials re-saved for a fresh connection.

## Solution
BuddyBoss updated the Zoom documentation for the current Zoom Developer interface (Zoom Integration setup, Zoom Meetings and Webinars, Configure Zoom Settings guides). A fresh setup following the updated docs connected Zoom and populated the Account Email dropdown.
Use a Server-to-Server OAuth app, add the scopes listed in the updated docs (including user read access), activate the app, then re-enter the credentials in BuddyBoss and save.
Root cause: Zoom renamed its scopes and changed its Developer console, so the old guide led to missing scopes and the app could not list Zoom account users.
