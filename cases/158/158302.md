## Debugging steps
1. Reproduced on a test account: reset email arrives and the link opens the new password form, but saving the password redirects to the lost password page with error invalidkey.
2. Checked the browser network log: the wp-resetpass cookie is set when the link opens but is no longer sent with the POST to wp-login.php?action=resetpass.
3. Ruled out: caching plugins, security plugin, server time, cookie consent plugin (also switched off in testing), browser and device.
4. Checked the child theme functions.php and found a custom login CSS function that loads a CSS file from the parent theme folder while the file only exists in the child theme folder.
5. The missing file request was redirected back to the login page during the reset, which cleared the reset cookie and caused invalidkey.

## Solution
In the child theme custom login CSS function, load the file from the child theme folder by changing the template URI function to the stylesheet URI function:
```php
// before: get_template_directory_uri() . '/your-login.css'
get_stylesheet_directory_uri() . '/your-login.css'
```
Back up functions.php first, then test that the login page looks the same and the reset saves correctly.
Root cause: child theme code requested a login CSS file from the parent theme folder; the failed request redirected to the login page and cleared the wp-resetpass cookie before the new password was saved.
