## Debugging steps
1. Saw this during a burst of Pusher auth requests at app launch, while PHP-FPM workers were busy.
2. Some BuddyBoss REST calls, such as GET /wp-json/buddyboss/v1/members, returned HTTP 200 with a zero-byte body.
3. Ruled out: PHP fatal errors, web server errors, timeouts and 502/504 responses. None were logged.
4. The app takes the empty 200 as a success and keeps showing the loading skeleton. It does not retry or show an error. A manual reload sometimes clears it.

## Solution
No fix was confirmed in the ticket. As a workaround, reduce load at launch (for example, rate-limit the Pusher auth burst) so the endpoints return full responses, and reload the screen if it stays stuck.
Root cause: under heavy load, endpoints return an empty 200 response, and the app does not check for an empty body before rendering.
