## Debugging steps
1. Ruled out: Services ID and Return URL, since Apple accepted the request and showed its consent screen.
2. Checked the Apple settings under BuddyBoss > Settings > General > Registration: Private Key ID held the Team ID instead of the Key ID of the Sign in with Apple key.
3. The settings page showed "Token generation failed: Private key format is not valid!" because the saved private key was missing its BEGIN and END lines.
4. After fixing the key, Verify Settings in Chrome still went back to the sign-in page: Apple posts its response cross-site, so Chrome drops the login cookie (SameSite) and the site does not see the admin as logged in.

## Solution
Put the Key ID of the Sign in with Apple key in Private Key ID, keep the Team ID in Team Identifier, and paste the full .p8 file contents including the BEGIN and END lines. Then run Verify Settings right after logging in, in a browser that sends the login cookie on the Apple callback (Firefox worked where Chrome failed), tick the Apple box and save.
Then enable Sign in with Apple on the App ID, regenerate the iOS signing certificates and provisioning profiles in BuddyBoss App, and request new iOS and Android builds.
Root cause: wrong Key ID and an incomplete private key stopped token generation, and the Chrome SameSite cookie rule blocked verification on the Apple callback.
