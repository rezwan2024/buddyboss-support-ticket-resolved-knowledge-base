## Debugging steps
1. Reviewed the scanner report: Elementor Pro 4.2.1 rated critical, LiteSpeed Cache 7.8.1 high, AutomatorWP 5.8.4 medium.
2. Confirmed the Elementor Pro report is real and fixed in Elementor Pro 4.2.2; it only applies when a published Elementor form has a file upload field.
3. Ruled out: the scanner's "actively used in attacks" label; public advisories showed no real-world cases for this report, the label came from an older unrelated Elementor Pro report.
4. Ruled out: BuddyBoss changes to Elementor Pro core files; the DFY build does not modify them, so updating does not break it.
5. Checked licensing: Elementor Pro and AutomatorWP need an active license on the site to get updates (Elementor > License in wp-admin).
6. To see if AutomatorWP is used, open AutomatorWP > Automations; an empty list means nothing depends on it.

## Solution
Update Elementor Pro to 4.2.2 or later, and LiteSpeed Cache and AutomatorWP to their current versions, on staging first, then click through key templates and the member dashboard before updating production. Deactivating a plugin is not a substitute for updating it, since the files stay on the server. Remove a DFY-installed plugin only after confirming nothing on the site uses it.
Root cause: outdated third-party plugins installed with the DFY build were flagged by the scanner; the plugin vendors fixed them in newer versions.
