## Debugging steps
1. Confirmed that App builds, Test and Release alike, are requested from the primary website, and the plugin version check runs before the build type can be chosen.
2. Ruled out: requesting a Test Build while the primary site stays on older plugin versions. The check blocks it and cannot be skipped.
3. Ruled out: building from the primary site, then using the Test App's Switch Connected Site (shake menu) to point it at the Secondary site. The version check on the primary site still forces the update first.
4. An older Test Build would not install on a registered device. That points to an expired Test Build signing certificate, not to device registration.
5. Product team confirmed that generating Test Builds from the Secondary website will not be added. The build is tied to the primary site at a structural level (version check, build configuration, App license connection).

## Solution
Workaround: get a second BuddyBoss App license, connect it to a separate test website that is a copy of the live site, and generate Test Builds from that test site. Update and test plugins there with its Test Build first, then update the live site. The test app does not need to be published to the stores, because Test Builds install directly on registered devices.
Root cause: by design, App builds can only be generated from the primary website once its BuddyBoss plugins are on the latest versions. The Secondary website cannot be a build source.
