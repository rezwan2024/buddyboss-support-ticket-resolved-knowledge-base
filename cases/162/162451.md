## Debugging steps
1. Checked how Send Group Message picks recipients: selecting all members loads every group member as a recipient, so there is no fixed member limit.
2. Checked the Private Reply (BCC) flow: above 20 recipients, members are split into batches of 20 and handled by the background process, not one long request.
3. Checked email notifications for new group messages: above 20 recipients they are queued and sent in batches of 20 in the background. The same applies to Group Thread.
4. Checked the background runs: each run stops before the PHP time or memory limit and then picks up the next batch. WP-Cron acts as a healthcheck that restarts the queue if it pauses.

## Solution
No limit on recipients. Large sends run in background batches of 20, so they avoid the PHP mail timeout but can take a while to reach everyone. If WP-Cron is disabled or the site gets little traffic, set up a real server cron job that calls wp-cron.php.
The batch size comes from the filter bb_email_queue_min_count, which defaults to 20.
Root cause: Question about how it works. Group messages and their emails are queued and processed in batches by a background process, with WP-Cron restarting the queue when it pauses.
