## Debugging steps
1. Checked the bbapp folder under wp-content/uploads (on multisite, under the subsite uploads folder) for stored credential files.
2. Found Firebase service account JSON, APNs .p8 key, .p12 push certificates, CSR .key/.csr and Android .jks keystore stored there.
3. Confirmed the csr and keystore subfolders have no index.html, no .htaccess and no deny rule, and the plugin has no code that writes one. Protection relied only on hashed filenames.
4. Confirmed the files are only blocked when the server has directory indexing turned off; with indexing on the folders list their contents.
5. Matched the report to a known security issue and escalated it to the product team.

## Solution
Update the BuddyBoss App plugin to v3.2.7 or later, which adds access protection for the credential folders.
Workaround until updated: add a server deny rule (nginx location block or Apache .htaccess deny) for the uploads bbapp credential folders and keep directory indexing off.
If credentials may have been exposed, check the access logs and rotate the keys if any outside request reached them.
Root cause: the plugin wrote signing keys and service account credentials into the publicly served uploads folder without shipping any access control.
