## Debugging steps
1. Confirmed cached logged-out pages load normally; the slowness is on uncached pages for logged-in users, even simple ones like login, checkout and a plain text page.
2. Timed several logged-in clicks: about 6.3 s total, of which about 5.2 s was server time before the first byte, about 0.8 s browser render.
3. Ruled out: database (about 0.13 s per page) and frontend assets, scripts, Elementor and Cloudflare, which only affect the last 0.8 s.
4. Checked PHP OPcache status on the server: 125 MB of 128 MB used, hit rate about 11% instead of above 99%, so PHP code was recompiled on most requests.
5. Server logs showed many slow background requests at peak hours from Rank Math Analytics URL Inspection and Wordfence scans.

## Solution
Ask the host to raise OPcache and restart PHP-FPM: opcache.memory_consumption 256 MB (or 512 MB), opcache.interned_strings_buffer 32 to 64 MB, opcache.max_accelerated_files about 20000. After the host applied it, server time dropped by about 44% with no theme change.
Also turn off or reduce Rank Math URL Inspection and schedule Wordfence scans for quiet hours. Refund was declined as the purchase was outside the 14-day window; refunds go through an Account and Billing ticket.
Root cause: the server OPcache was too small and full, so PHP for WordPress, the theme and all plugins was recompiled on almost every uncached request.
