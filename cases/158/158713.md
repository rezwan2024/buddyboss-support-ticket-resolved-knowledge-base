## Debugging steps
1. Recipient got a "New message from" email with the correct sender name and text, but the avatar and profile link of a different member whose email went out earlier in the same run.
2. Checked token__message() in bp-core/classes/class-bp-email-tokens.php: $_message_sender_id is only set when empty, and BP_Email_Tokens is created once per request, so the first sender's ID sticks for every later email.
3. Checked messages_notification_new_message(): 1:1 messages do not pass the sender.id token (group messages do).
4. Reproduced on a test site through the messages digest path with several senders in one run; same code in 3.4.4 and 3.5.0.

## Solution
Update BuddyBoss Platform to 3.6.2 or later, where the fix was released.
Root cause: the email token class kept the first sender's ID for the whole request instead of using each email's own sender.id, so later emails showed another member's avatar and profile link.
