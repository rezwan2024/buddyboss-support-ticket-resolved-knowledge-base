## Debugging steps
1. Narrowed it down one variable at a time: plain comments, replies and mentions open fine; any reaction on a comment crashes the app, in both Emotions and Likes mode. A reaction on the post itself is fine.
2. Ruled out: the site. Server logs show 200 on every app request and the PHP error log is empty; the device logcat shows the crash fully inside the app bundle (titleTrim while AppList renders a comment cell).
3. Ruled out: custom app code. A build with the custom code branch disconnected crashed the same way.
4. Ruled out: stored reaction data. The same reaction works on posts and crashes only on comments.
5. A newer app build, made later with the current app core, opened reacted comments without a crash on the same site and plugin versions.

## Solution
Start a new app build from AppCenter so it carries the latest app core, then re-enable Enable Reactions for Activity Comments. Reacted comments load normally on iOS and Android.
Workaround until then: turn off Enable Reactions for Activity Comments in the Platform settings (reactions on posts can stay on).
Root cause: app core bug in the comment row renderer (titleTrim) when a comment has a reaction, fixed in a later app core release.

## Customer note
Said the crash is fixed on the newer Android and iOS builds with comment reactions on and asked to close the ticket.
