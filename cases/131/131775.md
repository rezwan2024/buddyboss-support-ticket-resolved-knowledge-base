## Debugging steps
1. Reproduced: new user buys the locked course in the app with a test purchase, the app says the purchase succeeded, but purchase history shows access revoked at once.
2. Ruled out: web setup. Users who bought on the web (WooCommerce Memberships granting the LearnDash course) get access in the app.
3. Ruled out: integration type. The same revoke happens with WooCommerce Memberships, LearnDash Group and LearnDash Course integration types on the IAP product.
4. Checked the IAP product, membership and access group setup on the site and the store IAP setup in the developer account; configuration was correct.
5. Replicated on the BuddyBoss side and escalated to the developers as a product bug.

## Solution
Product bug in the BuddyBoss App plugin. A patch plugin was shared first, then the fix was released: update BuddyBoss products to the latest version and submit a new app build request, since the fix only takes effect in the app after a new build. Test with a fresh in-app purchase on a test device.
Root cause: bug in the BuddyBoss App In-App Purchase flow that revoked course access right after a valid purchase.
