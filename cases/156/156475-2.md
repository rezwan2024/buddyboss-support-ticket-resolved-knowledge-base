## Debugging steps
1. Tester had to turn on Settings > Privacy & Security > Developer Mode and restart the iPhone before the Ad Hoc Test App would open.
2. Ruled out: a BuddyBoss setting. Developer Mode is required by Apple (iOS 16 and later) for all Ad Hoc and development builds and cannot be turned off in the build.
3. Customer believed TestFlight needs an Xcode upload; checked that the plugin can upload the Release build directly.

## Solution
Use TestFlight with a Release App build, no Xcode needed:
1. Make sure the app record exists in App Store Connect with the same bundle ID.
2. BuddyBoss App > Configure > iOS Settings > Upload Configuration: select the Apple Account ID, paste a current App-Specific Password, save.
3. BuddyBoss App > Builds: generate a Release App build (not a Test App).
4. BuddyBoss App > Upload > Apple App Store: select the Release build, click Upload Build. It shows in App Store Connect under TestFlight in about 15 minutes.
5. In App Store Connect, invite testers under Users and Access, then add them in TestFlight > Internal Testing > Testers. Internal testing skips Beta App Review.
If the upload fails with an authentication error, create a new App-Specific Password (they are revoked when the Apple ID password changes). A build only shows in the upload list if its version and build number are higher than the ones already in App Store Connect.
Root cause: Apple requires Developer Mode for Ad Hoc builds; TestFlight installs need no UDID and no Developer Mode.
