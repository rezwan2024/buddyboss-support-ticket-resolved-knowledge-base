## Debugging steps
1. Asked where members were added "via users": it was the LearnDash "User Enrolled in Group" panel on the user profile, which writes LearnDash enrollment only, not BuddyBoss group membership.
2. Checked the API request: first call returned 200, repeat calls returned 500 with bp_rest_group_member_failed_to_join; the user was not listed under the group's Manage > Members in wp-admin.
3. Enabled WP_DEBUG and WP_DEBUG_LOG and collected the debug log and the full 500 response body; confirmed authentication was an application password.
4. Customer later reported the user IDs do get written to the BuddyBoss group members table on the API call.

## Solution
No confirmed fix. Use the group's Manage > Members screen in wp-admin (not the LearnDash user profile panel) to set BuddyBoss membership. Check the group members table for a leftover banned or unconfirmed row for that user and group (old invite, request or incomplete removal) that blocks a new membership, and check whether LearnDash group sync fails on the membership save. Custom API enrollment workflows were referred to the agency team; a reproduction on a clean site with only BuddyBoss and LearnDash would be escalated as a bug.
Root cause: not confirmed; likely a leftover non-confirmed membership row or a failure in the LearnDash group sync during the membership save.

## Customer note
Said the user IDs are being added to the group members table on the API call; no further reply.
