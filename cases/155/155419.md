## Debugging steps
1. Ruled out: reCAPTCHA keys and threshold, since native wp-login.php login worked with the same keys.
2. Reproduced the error on the MemberPress login page and on a page with the MemberPress login shortcode.
3. Disabling BuddyBoss reCAPTCHA for login made MemberPress login work again.
4. Found that BuddyBoss reCAPTCHA adds its token only to the WordPress core and BuddyBoss login forms, but its validation still ran on MemberPress login submissions, which have no token.
5. Ruled out: adding a second reCAPTCHA plugin, because No-Conflict Mode removes other reCAPTCHA instances from the page.

## Solution
Known bug, fixed in a later BuddyBoss release. Update all BuddyBoss plugins and recheck the MemberPress login.
Workaround until updating: disable BuddyBoss reCAPTCHA for login, or protect the MemberPress login with MemberPress Math Captcha (MemberPress > Settings > Account) or a Cloudflare Turnstile plugin with the "Only enable on default wp-login.php page" option unchecked.
Root cause: BuddyBoss reCAPTCHA validated login requests from third-party forms where it had not added its token.

## Customer note
Said that after updating all BuddyBoss plugins the reCAPTCHA works on the login page without any issues.
