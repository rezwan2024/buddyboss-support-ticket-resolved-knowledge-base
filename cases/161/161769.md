## Debugging steps
1. Checked the server PHP error log: fatal error from Plugin_Compatibility::disable_yoast_seo(), called by disable_conflicting_plugins() on the WordPress wp hook.
2. Deactivated BuddyBoss Sharing with Yoast SEO active: member profiles load again, so the Sharing add-on triggers the error.
3. Confirmed the cause: Yoast SEO 28.7 removed the old WPSEO_Frontend class, and Sharing calls it on member profile, group and single activity pages without checking that it exists.
4. Ruled out: Yoast SEO 28.6, which still has the class and does not trigger the error.

## Solution
Update BuddyBoss Sharing to 2.1.2 or later, which checks that the class exists before calling it.
Workarounds until then: keep Sharing deactivated, roll Yoast SEO back to 28.6, or add a temporary mu-plugin that removes the Sharing disable_conflicting_plugins callback on init and wp (Yoast may then add its own social tags on community pages, which is harmless). Delete the mu-plugin after updating.
Root cause: BuddyBoss Sharing called WPSEO_Frontend::get_instance() without a class_exists check, and Yoast SEO 28.7 removed that class.
