## Debugging steps
1. Ruled out: device registration, UDID, certificates and provisioning profiles. Regenerating signing certificates and provisioning profiles and requesting a new Test Build did not help.
2. Ruled out: the customer's iPhone. Several different iPhones, Safari and Chrome, and Developer Mode on all showed the same result, and a support iPhone failed the same way.
3. Ruled out: plugin conflict. With only BuddyBoss Platform and BuddyBoss App active the download still failed.
4. Checked the server with hosting access: the small file the iPhone downloads first when Install is tapped (the install manifest) had a PHP warning printed into it, about how the app icon was loaded, so iOS could not read it.

## Solution
In the site's PHP settings (.user.ini, or the hosting panel PHP settings) change `display_errors = On` to `display_errors = Off`, then wait a few minutes for it to apply and install the Test Build again. Warnings are still written to the server log. On shared hosting where several sites share one .user.ini, give the affected site its own copy so the other sites stay unchanged.
Root cause: display_errors was On, so PHP warnings were printed into the install manifest and iOS rejected it without showing an error.

## Customer note
Thanked the team for resolving the installation issue and said a separate site layout problem came from plugins they had turned off during testing.
