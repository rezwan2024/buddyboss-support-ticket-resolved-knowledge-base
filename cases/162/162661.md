## Debugging steps
1. Reproduced: typing a tag created in the backend into the new discussion tags field showed no suggestions.
2. Compared with a test site, where tag suggestions load as expected.
3. Conflict test with plugins deactivated one at a time: suggestions came back with Events Manager (7.4.12) deactivated.
4. Found both BuddyBoss and Events Manager use the same internal request name for tag search; Events Manager answered first with its own format, so the tags field could not read the response.

## Solution
Workaround: added a small code snippet with a code snippet plugin that applies only to the BuddyBoss discussion tags search request, so Events Manager stays active and keeps working. Test on staging first, then add the same snippet to live.
Root cause: Events Manager handles the shared search_tags request first and returns a format the BuddyBoss discussion tags field cannot read.
