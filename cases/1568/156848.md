## Debugging steps
1. Ruled out: server side. Every comment API request returned 200 and the PHP and web server error logs were empty for the crash time.
2. Isolated by adding one thing at a time to a post: plain comments, replies, mentions and reactions on the post itself opened fine. Any reaction on a comment crashed the app, in both Emotions and Likes mode.
3. Device log showed a fatal JavaScript exception in titleTrim while the app list rendered a comment row, all frames inside the app bundle.
4. Ruled out: custom app code. A build without the custom code branch still crashed.
5. Ruled out: stored reaction data. The same reaction worked on posts and crashed only on comments.
6. A newer app build opened the same reacted comments without a crash on Android and iOS.

## Solution
Start a new app build in AppCenter and install it. The newer app core renders reacted comments correctly. Until the new build is installed, turn off Enable Reactions for Activity Comments as a workaround so the app stops crashing.
Root cause: bug in the app's comment row rendering for comments with reactions, fixed in a later app core release.
