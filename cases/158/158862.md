## Debugging steps
1. Ruled out: server WAF and ModSecurity, the host found no matching denial in its logs for the 403 requests.
2. Ruled out: login rate limit, it only watches POST requests to the WordPress login page.
3. Noted that 403s from many different IPs are normal traffic: the app calls signup/form before login on every device to load the registration form, so the block is on the site itself (web server config or WordPress).
4. Check registration settings: BuddyBoss > Settings > General "Allow non-members to create new accounts" and BuddyBoss App > Settings > General "Allow registering a new account from within the app" must both be on.
5. Check privacy settings: BuddyBoss > Settings > Advanced > Privacy "Private REST APIs" and the "Private App" option in BuddyBoss App settings both restrict API access for logged-out users.
6. Check security or performance plugins (Wordfence, Solid Security, All In One WP Security, Perfmatters, Disable REST API) for an option that blocks the REST API for logged-out visitors, then run curl -i on the endpoint while logged out: a JSON body with a "code" value points to WordPress or a plugin, an HTML error page points to the web server config.

## Solution
No confirmed fix yet. Enable both registration settings, turn off Private REST APIs / Private App or allow the signup endpoint, and remove any plugin rule that blocks the REST API for logged-out visitors. Use the curl response body to find the source of the 403.
Root cause: not confirmed; most likely a WordPress-side setting or plugin blocking REST API requests from logged-out app users.
