## Debugging steps
1. Explained that the app renders native screens from the REST API, so header JavaScript can only run inside in-app WebView screens, not on Timeline, Messages or Groups.
2. Ruled out: caching. The customer disabled LiteSpeed Cache and the bubble still did not appear. Same result on iOS and Android.
3. Rebuilt the same setup on a test site with a Classic app build: the widget loaded on the website but not on any app screen, including an in-app web page screen.
4. Checked with the chatbot provider: the widget is supported on websites only, with no mobile app integration.

## Solution
Workaround: take the standalone chatbot link from the chatbot provider's dashboard (share settings) and add it to the app menu as a custom link, set to open inside the app. It opens the same bot as a full page.
Adding third-party widgets through the WordPress header is not a supported way to inject them into the app, so it can stop working on any update.
Root cause: the app does not read scripts from the WordPress header; the bubble worked before only by accident.
