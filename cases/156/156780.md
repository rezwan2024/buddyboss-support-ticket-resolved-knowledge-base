## Debugging steps
1. Confirmed the custom tab works in the Classic app and in the browser, and fails only in the Next Gen app on both iOS and Android.
2. Reviewed the custom tab code: registered with bp_register_group_extension and prints HTML. Ruled out: no redirect call in the PHP.
3. Checked the Next Gen group tab data: each tab ID is the tab's web slug (documents, photos and so on), with no page type or app page field to point a custom tab to an app page.
4. Checked BuddyBoss App > Settings > Compatibility > Custom Group Tabs: with it off the custom tab is hidden in the app, with it on a simple custom tab opened as a web page on a test site.
5. Ruled out the custom plugin: a plain custom group tab made without it showed the same kick-out on the customer's site.
6. Customer test: renaming the custom tab slug to a built-in slug such as photos made it open normally inside the app.

## Solution
No fix. The Next Gen app only opens its own screens for the group tab slugs it knows; any other tab opens as a web page and can break the in-app flow. Custom code support for Next Gen is not available yet, so the customer was pointed to custom development and to raise a feature request for a generic tab ID that maps to an app page.
Root cause: Next Gen (Flutter) app handles unknown custom group tab slugs differently from the Classic app and has no generic ID to route them to an app page.

## Customer note
Said the issue lies with the Next Gen app, that no effective solution was reached, and that they may move to another platform.
