## Debugging steps
1. Checked the Platform 1.7.5 source: no wp_robots hook, no bp_core_noindex function, bp_is_single_activity() not used for any robots directive.
2. Ruled out: the only noindex in 1.7.5 is an X-Robots-Tag header on media, video and document downloads, not on activity permalinks.
3. Compared with 2.0.0: same behavior.
4. Customer's own logged-out HTTP test of an activity URL returned 200 with index, follow.

## Solution
BuddyBoss Platform does not output noindex on single Activity pages. Look for another source: Settings > Reading > Search engine visibility, an SEO plugin or theme setting, or a server or CDN header.
To check, open the activity page in a private window, view the source and search for robots, then check the response headers for X-Robots-Tag.
Root cause: the noindex did not come from BuddyBoss Platform. It came from another plugin, setting or header.
