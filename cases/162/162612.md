## Debugging steps
1. Customer removed the featured image from the single post REST response with a rest_prepare_post filter; the image still flashed when the post opened.
2. Reproduced on a test app: the Next Gen app draws the single post screen natively from the post data already loaded by the Posts block list, before the single post response arrives.
3. Ruled out: a site-side fix, because the list data (with the featured image) is used first.
4. Checked the App Editor options for the single post screen: no setting or filter hides the featured image only on that screen.

## Solution
No built-in option. Hiding the featured image only on the single post screen needs a change in the app itself, so submit it as a feature request (Contact page, product Others, BuddyBoss App, Feature request) or use custom app development.
Root cause: The app renders the single post screen from the cached Posts block list data, which includes the featured image, so filtering the single post API response cannot stop the first render.
