## Debugging steps
1. Confirmed with the customer that the count is the bell in the BuddyBoss admin Inbox under BuddyBoss > Settings, not member notifications on the front end.
2. Dismissed one notice on the site: the bell dropped from 6 to 5, then went back to 6 after a reload and the notice was still listed as unread.
3. Saw in the browser network tab that the request saving the dismissal was refused by the server, while the count changed only in the browser.
4. On a test site the same action moved the notice to the Read tab, but it stayed listed under All.
5. Checked with the development team: the admin Inbox never deletes notices, dismissed ones are only marked read; the same Inbox is shared with other plugins such as MemberPress.

## Solution
No fix. Answered as by design: admin Inbox notices are never removed, only marked read. Logged as an improvement request to let dismissed notices be cleared or hidden from the count.
Root cause: the admin Inbox keeps all notices by design, and on this site the dismissal was not saved, so notices reverted to unread.

## Customer note
Said marking them read still reverts them to unread immediately and hopes the team fixes it.
