## Debugging steps
1. Reproduced on a clean test install: added a WordPress Page to the More menu, enabled "Always open in external browser", saved; the setting stayed enabled, so the issue was site specific.
2. Customer checked the Save Menu POST request: open_external = yes was sent and the save returned the "menu has been updated" notice, but the checkbox was unchecked after reload.
3. Ruled out: browser side, since the value is in the request and the save succeeds; the value is lost on the server or an old cached copy is shown.
4. Ruled out: font CORS console errors, which only affect font loading.
5. Site used a page and object caching plugin and a security firewall plugin, both suspects.

## Solution
Next steps given: clear all caches including the object cache, then reopen the menu item to see if the value was saved. If it still unchecks, run a plugin conflict test with only BuddyBoss Platform, BuddyBoss App and the theme active, with the caching and security plugins deactivated, on staging or in Troubleshooting Mode.
Root cause: Not confirmed; likely a stale object cache or a plugin dropping the value on save, since it saved correctly on a clean install.
