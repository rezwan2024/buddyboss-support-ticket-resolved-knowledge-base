## Debugging steps
1. Checked the error log: fatal TypeError in bp_show_hide_toolbar() during administrator sign-in, Platform 3.4.4, PHP 8.4, WordPress 7.1.
2. Reviewed the function source: $current_user_caps is set only when no old switched user exists or the old user ID differs from the current user ID, not when both IDs match.
3. Trigger: the administrator was restored through the host's admin login tool while the BuddyBoss Log in as (account switching) cookie, valid up to 48 hours, was still active, so null reached in_array().
4. Checked Platform 3.5.0: it still has the same code, so updating would not fix it and would remove a local patch.

## Solution
Temporary workaround the customer applied in the plugin file, right after the current user object is loaded in bp_show_hide_toolbar(), keeping the existing branches:
```php
// Always initialize capabilities when a restored user matches the switching cookie.
$current_user_caps = isset( $user->allcaps ) && is_array( $user->allcaps ) ? $user->allcaps : array();
```
Support confirmed the analysis matches the source code and advised not to update Platform yet, since an update overwrites the patch; an update-safe workaround was still pending reproduction.
Root cause: bp_show_hide_toolbar() leaves $current_user_caps unset when the switched-from user ID equals the current user ID.
