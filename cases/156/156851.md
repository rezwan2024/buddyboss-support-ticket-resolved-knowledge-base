## Debugging steps
1. Asked the customer to update BuddyBoss Platform and Platform Pro to the latest versions. Problem stayed after the update.
2. In BuddyBoss > Settings > Advanced, turned off Content Counts and set Page Requests to 1 to cut per-user queries.
3. Reproduced on the cart page with a query profiler, logged in, one product in the cart: about 470 queries in total, only about 140 from BuddyBoss Platform, the rest from other plugins doing extra work while BuddyBoss is active.
4. Ruled out: a member loop on the cart page. The profile visibility and suspend check ran only twice per page load, for the logged-in user only.
5. The profiler showed Redis available on the server but no persistent object cache plugin active, with over 90,000 object cache lookups rebuilt on every request.

## Solution
Install and enable the Redis Object Cache plugin (persistent object cache) so repeated option and meta lookups are cached between requests. This lowers the cost of the queries, not the count. If the host runs Redis for other sites, use a dedicated database index.
Next step was to find which hook or rendered element makes other plugins run extra queries while BuddyBoss is active.
Root cause: Not fully found; most extra queries came from other plugins reacting to BuddyBoss being active, made worse by no persistent object cache.
