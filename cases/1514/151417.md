## Debugging steps
1. Checked wp-content/uploads/bbapp/ (or uploads/sites/<id>/bbapp/ on multisite) for the signing keys and service account files.
2. Confirmed the csr/ and keystore/ subfolders had no index.html, no .htaccess and no deny rule, and the plugin writes none.
3. Confirmed the files were only protected by unguessable filenames, so any host with directory indexing on would list them.
4. Confirmed as a known plugin bug and escalated to the product team.

## Solution
Update the BuddyBoss App plugin to 3.2.7 or later, which fixes the missing access protection for the credential folders.
Workaround until updated: add a server deny rule (nginx location block or Apache .htaccess) for the bbapp csr/ and keystore/ folders under uploads, and keep directory indexing off.
Root cause: App plugin 3.1.0 stored push and signing credentials in the public uploads directory without any access control.
