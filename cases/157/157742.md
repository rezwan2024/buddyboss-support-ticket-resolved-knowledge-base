## Debugging steps
1. Customer saw a correct admin new user email, then within the same minute a second email with the same template but no subject and no recipient, which the SMTP plugin rejected. Custom mail logging code on the site showed BuddyBoss Platform as the source of both.
2. Ruled out: standard Platform behaviour. A clean install with only BuddyBoss Platform and BuddyBoss Theme sent the admin notification once per registration and no empty email.
3. Noted the empty email targets a user, not the admin, so it is likely the member registration or activation email, not a copy of the admin notification.
4. Asked for the custom mail logging code, the registration method (default BuddyBoss page or a membership or form plugin), and Platform, Theme, WordPress, PHP and SMTP plugin versions.

## Solution
Not resolved in the ticket. Next steps given: run a conflict test on staging with only BuddyBoss Platform, the SMTP plugin and BuddyBoss Theme active, then re-enable plugins one at a time. Check BuddyBoss > Emails that every registration email exists and has a subject; if one was edited or trashed, reinstall the default emails from BuddyBoss > Tools > Repair Community (this replaces customised emails, so back up first).
Root cause: not confirmed; likely a site specific plugin, registration method or missing or edited registration email template firing the email without its data.
