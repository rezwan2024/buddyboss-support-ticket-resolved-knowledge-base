## Debugging steps
1. Checked which BuddyBoss files the home page loads: bp-nouveau (buddypress.min.css), icons-map, mentions, bp-zoom CSS and JS while Zoom was off, and MemberPress Courses and Tutor LMS styles even though MemberPress was not installed.
2. Ruled out: the react-dom render-blocking file comes from the Gutenberg plugin, not BuddyBoss.
3. Ruled out: WP Rocket and Jetpack Boost did not remove these files.
4. Measured rule usage on the home page: buddypress.min.css matched under 1% of its rules. Only the hidden Report and Block Member modal in the footer relies on it.
5. Ruled out: a PHP warning seen after adding the snippet came from a separate custom snippet with an undefined variable, not from the dequeue code.

## Solution
Add a PHP snippet in a code snippet plugin that dequeues the BuddyBoss assets on the front page only, and keep the inline style that hides the footer modal. This saved almost 1 second on mobile with no layout change.
```php
add_action( 'wp_enqueue_scripts', function () {
	if ( ! is_front_page() ) { return; }
	foreach ( array( 'bp-nouveau', 'bp-nouveau-icons-map', 'bp-mentions-css', 'bp-zoom', 'bb-meprlms-frontend', 'bb-tutorlms-admin' ) as $h ) { wp_dequeue_style( $h ); }
	foreach ( array( 'bp-zoom-js', 'bb-meprlms-frontend', 'bb-tutorlms-admin' ) as $h ) { wp_dequeue_script( $h ); }
}, 100 );
add_action( 'wp_head', function () {
	if ( is_front_page() ) {
		echo '<style>.bp-hide,.bbm-model-wrap,.modal-mask,#bp-report-content,.bp-report-form-err{display:none !important;}</style>';
	}
} );
```
Root cause: BuddyBoss Platform and Platform Pro enqueue their core and component assets on every page, including non-community pages, and disabling the Zoom component does not stop its files from loading.
