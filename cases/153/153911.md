## Debugging steps
1. Confirmed the conditional shortcodes work on the website but not inside app-approved blocks in the app.
2. Checked how the app renders content: app-approved blocks are rendered natively from block data sent over the REST API, with no PHP run at that stage.
3. Ruled out: a setting to turn on server-side shortcode execution. No such option exists in BuddyBoss App.
4. Ruled out: a custom dynamic block with a render callback that runs do_shortcode(). Any block outside the supported set falls back to WebView, same as the Classic block.
5. Noted that membership plugin conditionals check that plugin's own session and cookie state, which app requests do not carry the same way, so they can quietly return the logged-out or lowest-level content.

## Solution
Not supported in app-native blocks. Workarounds: split content into separate LearnDash lessons or courses per student level and enroll students by level through course access, or segment content with BuddyBoss member types or groups. The only full option is custom development: a custom REST endpoint that checks the user's level on the server and returns only allowed content to a custom app screen.
Root cause: app-approved blocks render natively in the app without running PHP, so third-party shortcode logic never executes.
